# KISEC Cyber Escape

사이버보안 실태평가 문제를 방탈출 형식으로 풀어보는 모바일 웹 게임입니다.

## 실행

```bash
pnpm install
pnpm dev
```

관리자 기능을 사용할 때는 별도 터미널에서 API 서버도 실행합니다. Node.js 22 이상을 권장합니다.

```bash
cp .env.server.example .env.server
ADMIN_PASSWORD='12자 이상의 관리자 비밀번호' pnpm server:hash-password
pnpm server
```

생성한 비밀번호 해시는 `.env.server`의 `ADMIN_PASSWORD_HASH`에 넣습니다. 관리자 비밀번호,
세션 비밀키, Supabase `service_role` 키는 서버 전용 값이며 `VITE_` 접두사를 붙이거나
저장소에 커밋하면 안 됩니다.

## 품질 검사

```bash
pnpm check
```

## 관리자 화면

관리자 화면은 `/admin`에서 확인할 수 있습니다. 로그인 정보는 브라우저 코드가 아니라 API 서버에서
검증하며, 성공한 세션은 JavaScript로 읽을 수 없는 `HttpOnly` 쿠키에 저장됩니다. 문제·기관·배포·
응시 조정·순위·상품 관리 요청은 동일 출처 확인과 CSRF 토큰 검사를 통과한 경우에만 서버가
처리합니다. 운영 환경에서는 웹앱과 `/api`를 같은 HTTPS 도메인으로 연결하는 리버스 프록시 구성을
권장합니다.

로컬 UI와 흐름을 확인할 때만 `.env.local`에서 `VITE_ADMIN_DEMO_MODE=true`, `.env.server`에서
`ALLOW_LOCAL_DATA=true`를 사용할 수 있습니다. 운영 환경에서는 로컬 데이터 모드가 강제로
차단되며 Supabase 프로젝트 연결이 필요합니다.

```bash
cp .env.example .env.local
```

1. Supabase SQL Editor에서 `supabase/migrations` 안의 SQL을 파일명 순서대로 실행합니다.
2. `.env.server`에 `SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY`를 설정합니다.
3. `NODE_ENV=production`, `ALLOW_LOCAL_DATA=false`, 충분히 긴 무작위 `SESSION_SECRET`으로 서버를
   실행합니다.
4. 웹 서버에서 `/api`를 API 서버로 프록시하고 HTTPS를 적용합니다.

마지막 마이그레이션은 기존 브라우저 관리자 쓰기 정책을 제거합니다. `service_role` 키는 모든 RLS를
우회할 수 있으므로 반드시 API 서버의 비밀 저장소에서만 관리해야 합니다.

문제 가져오기는 `문제지 1부 + 해답지 1부`를 한 세트로 받습니다. 두 파일은 각각 PDF, HWP,
HWPX 중 하나를 선택할 수 있으므로 `문제지 PDF + 해답지 HWP` 조합도 가능합니다. 원문은 같은
세트 식별자로 private Storage 버킷에 저장되며, 문항 번호가 일치하는 문제와 정답만 결합합니다.
번호를 연결하지 못하거나 정답이 보기 범위를 벗어나면 임의로 보정하지 않고 등록 대상에서 제외합니다.

PDF는 PDF.js로 페이지 좌표를 기준으로 읽기 순서를 복원하고, HWP/HWPX는 `@mdgate/hwp`로
Markdown을 추출합니다. 스캔 PDF는 텍스트 층이 없으므로 운영 서버 앞단에 OCRmyPDF와 한국어
Tesseract를 두거나 문자 인식된 PDF로 변환한 뒤 올려야 합니다. 구형 바이너리 HWP의 복잡한 표와
배치까지 원본과 동일하게 처리해야 하는 운영 환경에는 한컴 Hwp SDK 같은 정식 문서 필터 도입을
권장합니다. 자동 추출 결과는 즉시 공개되지 않고 항상 `초안`으로 저장되므로 관리자가 문제·보기·
정답·해설을 확인한 뒤 공개해야 합니다.

게임은 Supabase가 연결된 운영 환경에서 `공개` 상태 문제를 번호순으로 30개 불러옵니다. 공개
문제가 30개보다 적거나 조회에 실패하면 정적 문제로 조용히 대체하지 않고 시작을 막아, 화면에
보이는 문제와 서버가 검증하는 정답이 달라지는 상황을 방지합니다. Supabase가 없는 로컬 게임
개발 환경에서만 기존 `src/data/questions.ts`를 사용합니다.

## 기관별 배포와 응시 제한

관리자는 `/admin/institutions`에서 기관을 등록하고 배포 링크를 생성할 수 있습니다. 배포 링크로
접속한 참여자는 요원명과 부서명, 기관에서 안내한 고유 참여 코드를 입력합니다. 참여 코드는 원문
대신 해시로 저장되며, 같은 배포와 참여 코드 조합에는 응시 기록이 하나만 생성됩니다. 요원명과
부서명은 응시 현황, 순위, CSV 운영 자료에 함께 표시됩니다.

- 진행 중 이탈: 같은 참여 코드로 다시 접속하면 서버에 저장된 단계부터 이어서 진행합니다.
- 완료 후 재접속: 문제 화면으로 돌아가지 않고 완료 안내 화면을 표시합니다.
- 예외 처리: 관리자가 응시 기록을 재개·무효 처리하거나, 사유를 남기고 답안까지 초기화할 수 있습니다.
- 점수 보호: 각 문항의 첫 답안만 저장하고 DB의 공개 문제 정답으로 점수를 다시 계산합니다.

운영 전에는 문제 관리 화면의 `기존 게임 문제 동기화`를 실행해 공개 문제 30개를 DB에 등록해야
합니다. 참여 코드는 기관에서 사람마다 다르게 발급해야 단일 응시 제한을 정확히 적용할 수 있습니다.

## 탈출 순위와 상품 지급

`/admin/rankings`에서 배포별 완료 순위를 확인할 수 있습니다. 순위는 클라이언트 화면의 점수가
아니라 서버에 처음 기록된 답안을 기준으로 계산하며, 아래 순서를 차례로 적용합니다.

1. 검증된 정답 수가 많은 참여자
2. 시작부터 탈출 완료까지 소요 시간이 짧은 참여자
3. 탈출 완료 시각이 빠른 참여자

관리자는 현재 1위를 수상자로 확정하고 `1위 선정 → 수상자 안내 → 지급 완료` 상태와 메모를
기록할 수 있습니다. 운영 자료는 배포별 CSV로 내려받을 수 있습니다. 무효 처리된 응시 기록은
순위에서 자동 제외됩니다.

## 구조

- `src/screens`: 화면 단위 컴포넌트
- `src/components`: 여러 화면에서 재사용할 수 있는 UI
- `src/game`: 게임 규칙, 설정, 질문 파싱 로직
- `src/data`: 보안 문제 데이터
- `src/admin`: 관리자 데이터 모델, 문서 추출, 저장소 접근 로직
- `server`: 관리자 인증, 세션, 권한 검사, 관리자 데이터 API
- `supabase/migrations`: 운영 데이터베이스 스키마와 서버 전용 권한
- `public`: 앱에서 실제 사용하는 이미지와 아이콘
